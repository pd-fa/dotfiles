# Browser

Replaces Arc, which went the way of every browser that treats the account as the
product.

| Was | Now | Why it moved |
| --- | --- | --- |
| Arc | Firefox | Arc is in maintenance while The Browser Company ships Dia; both gate core behaviour behind a login |
| Arc spaces | Sidebery | Vertical tabs, workspaces and split view, configured from a file rather than a synced account |
| — | Tridactyl | Keyboard driving, and the only one that opens the real `nvim` for a text field |

## Why Firefox and not Chromium

The deciding constraint is not rendering engine or extension catalogue — it is
whether the browser's own chrome can be themed from `theme/palette.toml`.

| | Chrome themeable from a file? | Account-free? |
| --- | --- | --- |
| **Firefox** | `userChrome.css` — a documented profile path | Yes |
| Zen | Yes, but against its own restyled IDs | Yes |
| Vivaldi | Behind an experimental flag that has moved between releases | Yes |
| Chrome | No | Pushes hard |
| Safari | No | — |

Chrome and Safari expose no supported way to restyle browser chrome, so either
would be the one permanently off-palette app on the machine. Zen is Firefox with
the Arc shape pre-built, but it restyles its own chrome — a `userChrome.css`
written against it targets internal IDs that shift release to release, which is
strictly more fragile than writing against stock Firefox for the same result.

Vivaldi is the strongest Chromium option and is genuinely account-free, but its
custom-UI-CSS support is a flagged experiment rather than a supported path.

## What lives where

```
firefox/user.js                        about:config, rendered from the palette
firefox/policies.json                  add-on auto-install + telemetry off
firefox/chrome/userChrome.css          browser chrome
firefox/chrome/userContent.css         Firefox's own about: pages
firefox/sidebery/pinknight.css         pasted into Sidebery's styles editor
firefox/sidebery-settings.json         Sidebery's own export
tridactyl/tridactylrc                  read from ~/.config natively, no symlink
tridactyl/themes/pinknight.css         loaded by `colourscheme pinknight`
```

Everything except `policies.json`, `tridactylrc` and the Sidebery export is
generated by `theme/sync-theme.py` — edit the template, never the rendered file.

## The three things that are not declarative

Worth knowing before assuming a rebuild is complete:

1. **Firefox profile paths carry a random prefix**, so the destination cannot be
   declared the way every other config here can. `bootstrap.sh` discovers
   `*.default-release` and symlinks `user.js` and `chrome/` into it. A machine
   that has never launched Firefox has no profile — the bootstrap says so and
   converges on the next run.

2. **`policies.json` lives inside the app bundle.** It is the only path Firefox
   reads on macOS, and a cask upgrade replaces the bundle and drops the file.
   Re-running the bootstrap restores it. The telemetry prefs are duplicated in
   `user.js` deliberately so the gap between upgrade and re-run is not a hole.

3. **Sidebery settings are extension storage, not a file.** Configure once, then
   Sidebery settings > Help > Export, saved to `firefox/sidebery-settings.json`.
   That export is a snapshot and will drift; `firefox/sidebery/pinknight.css` is
   the generated part and stays canonical for colour.

## Tridactyl needs its native messenger

`:installnative`, once per machine. Until it runs, Tridactyl cannot read files
from disk at all — `tridactylrc` is ignored and the theme fails to load. This is
the single most common reason the setup looks like it did nothing.
